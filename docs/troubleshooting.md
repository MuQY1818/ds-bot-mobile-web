# 故障排查

先分清是入口打不开、需要登录，还是页面内的会话加载问题。保留错误文字，不必一开始就重装或清空数据。

## 手机打不开地址或一直转圈

1. 确认电脑已唤醒，DSH 仍在运行。
2. 使用私网入口时，确认手机和电脑都已连接对应网络；从 Wi-Fi 切到蜂窝后也要检查。
3. 在手机浏览器直接打开普通 HTTPS 入口，区分域名无法访问和页面加载缓慢。
4. 电脑重启后若端口变化，维护者需检查转发目标。入口配置见[网络连接](remote-access.md)。

不要在手机使用电脑的 `localhost` / `127.0.0.1` 地址。

## 手机显示 authentication required

这说明请求已到达宿主，但当前浏览器没有有效登录。回到电脑，从账户菜单 **手机访问 → Web** 刷新登录入口，再在需要使用的手机浏览器中扫码登录。

不要手工替换登录链接里的域名。二维码或链接复制失败时，展开面板中的手动复制选项。普通地址可达，不代表已登录。

## 添加桌面后又要登录

桌面入口可能使用与原浏览器窗口不同的浏览环境。请在该入口中完成登录，登录后再使用同一普通地址。必要时重新从电脑生成登录链接。不要把含登录凭据的完整链接公开分享。

## 添加桌面或长时间后台后打开很慢

先确认电脑与私网状态，再看慢发生在哪一步：

| 现象 | 优先处理 |
| --- | --- |
| 域名迟迟打不开 | 检查网络、私网连接和电脑唤醒 |
| 整个界面首次加载慢 | 浏览器可能重新加载首页资源；冷启动优化仍在开发 |
| 界面已经显示，长会话历史慢 | 等待历史同步，观察短期返回是否复用；记录具体会话规模 |
| 已出现消息但连接仍恢复中 | 等待宿主连接恢复，不连续重复发送 |

刷新或系统回收网页后，当前页面内的会话缓存不会一直保留。反复刷新也会重新触发资源加载。

## 找不到“手机访问”或仍是桌面界面

- 确认 `ds-bot-mobile-web` 已在日常使用的 DSH 环境中安装并启用，随后刷新。
- 账户菜单入口不可见时，从官方插件管理器的本包配置页打开手机访问。
- 手机布局关闭时，在插件配置页重新启用布局；宽屏本来就使用桌面界面。
- 从旧包迁移后异常，查看[旧包名迁移](installation.md#从旧包名迁移)。

## 入口未就绪或地址未受信任

面板里应填写已经配置好的普通 HTTPS 地址。保存地址不会建立隧道或修改宿主信任；先按[网络连接](remote-access.md)准备入口，再刷新面板。

## 发送后键盘没有收起

确认电脑已更新到 0.4.2 或更新版本，手机刷新到了新页面，并且处于手机布局。该行为只在有效消息开始提交时触发；空消息、Shift+Enter 换行和不可发送状态保持输入。浏览器或输入法仍有差异时，请报告设备和复现步骤。

## 安装失败

查看插件管理器的具体错误。若提示依赖发布时间限制，等待策略允许后再试；不要删除锁文件或全局关闭策略。更新一个布局插件不需要重建团队。
