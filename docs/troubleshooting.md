# 故障排查

先记录发生问题的设备、浏览器、插件版本，以及屏幕上的完整错误文字。网络连通、DSH 登录和移动布局加载是不同环节；从最先失败的一步检查，不要一开始就重装 DS Bot。

本页对应 v0.1.4。扫码入口需要在电脑本机打开；手机端继续使用宿主的官方登录会话。

## 手机显示 authentication required

常见错误：

```text
dsh web authentication required; reopen the URL printed by dsh web.
```

这表示该次请求已经到达 DSH 宿主，但手机浏览器没有有效的认证会话。能访问域名，不等于已经登录；这条错误也不能证明移动插件没有安装。

按下面的顺序处理：

1. 在电脑上打开已登录的 DSH，通过宿主已有的官方方式重新获取登录链接。
2. 确认链接对应当前使用且手机可达的入口；完整网络配置见[远程访问](remote-access.md)。
3. 在实际使用的手机浏览器扫码或打开完整官方登录链接。
4. 等待登录完成，再从同一个浏览器、同一个入口进入会话列表。

在电脑本机的 DS Bot 左下角账户菜单中选择“手机访问”，刷新入口后扫码或复制完整登录链接。若浏览器拒绝剪贴板，展开面板的“手动复制登录链接”。不需要先清空全部 cookie。

不要手动把本机签名 URL 里的 `localhost` 或 `127.0.0.1` 改成其他主机名。签名可能与入口主机绑定；修改后即使请求能到达，也可能被拒绝。应先配置可达入口，再生成登录链接。

如果仍然出现同一错误，检查：

- 是否在手机相机扫码后换到了另一个浏览器，或进入了无痕窗口。
- 是否用了之前重启前的链接，或从另一个域名登录后又回到旧入口。
- 复制的链接是否完整，有没有被聊天软件截断或改写。
- 当前宿主是否拒绝这个入口的 Host／Origin，或远程代理是否没有按配置传递请求。

重新获取一次链接并在目标浏览器打开；仍失败就保留错误状态和发生时间，交给维护者检查。不要关闭认证、Host／Origin 检查来绕过，也不要在 Issue 中上传完整登录 URL、二维码、cookie 或 token。

## 手机打不开地址或一直连接超时

如果浏览器报无法连接、无法解析域名或连接超时，先检查网络。此时还不能判断认证或插件是否正常。

1. 确认电脑没有休眠，DSH 仍在运行。
2. 在电脑打开原来的 DSH 页面，确认宿主本身可用。
3. 确认手机访问的是手机可达的入口，而非 `127.0.0.1` 或 `localhost`。这些地址在手机上只指手机自己。
4. 按所用网络方案检查两端是否互通。相同 Wi-Fi 名称不一定代表设备能互访，访客网络可能隔离设备。
5. 如果使用 Tailscale，确认两端按你的配置连入同一私网，并有相应访问权限。Tailscale 是可选网络方案，不由移动布局插件安装或启动。
6. 如果使用代理或 HTTPS 入口，检查它是否仍指向当前宿主，证书是否有效。不要通过忽略证书警告来掩盖配置错误。

网络入口的具体配置见[远程访问](remote-access.md)。不要把电脑进程重启前的临时端口当作长期固定地址，也不要为了“连得上”随意把整个宿主暴露到公网。

## 找不到“手机访问”菜单

v0.1.4 的入口位于 DS Bot 左下角账户按钮弹出的菜单，和“Bot 设置”并列。

1. 在电脑官方管理器确认 `dsh-mobile-layout-local` 版本及启用状态，再刷新页面；旧版没有这个入口。
2. 确认当前是 DS Bot 模式，没有打开另一套宿主或隔离测试页。
3. 如果 DS Bot 更新导致菜单适配失效，从 DSH 插件设置页打开“手机布局”，再点击其中的“手机访问”。
4. 若这两个入口都不存在，记录 DSH、DS Bot 和插件版本，报告兼容问题。

插件没有修改原 DS Bot 菜单源码；账户菜单入口是可清理的 DOM 适配，需要在上游更新后回归。不要猜测某个私有登录路径在所有安装中都存在。

## 菜单能打开，但二维码或复制链接不可用

按面板显示的具体提示处理：

- 显示电脑本机地址或入口未设置：按[远程访问](remote-access.md)配置可达的 HTTPS 地址，再“保存并检查”。
- 地址尚未加入信任列表：先在宿主配置精确 Host／Origin 信任。单独保存插件地址不会放宽宿主权限。
- 提示需要 HTTPS：换成已有的 HTTPS 入口，不要通过忽略证书错误继续。
- 提示在电脑本机操作：远程页面不能生成其他设备的登录链接，回到电脑本机 DS Bot 打开面板。
- 暂时无法取得入口：确认插件宿主部分和 DSH Web 已启用，检查版本，再关闭面板重开。
- 地址未保存：确认当前 profile 允许修改设置。如果命令行或更高优先级配置覆盖了此字段，需要由维护者处理该覆盖；不要重复点击保存。
- 复制失败：展开“手动复制登录链接”，选中内容后复制；不要从启动日志里找凭据。
- 扫码仍认证失败：按上面的[认证错误处理](#手机显示-authentication-required)核对浏览器与入口。生成二维码不会自动建立私网连接。

宿主重启后需要重新获取链接。关闭弹窗或“刷新入口”不代表撤销旧链接；如凭据已泄露，按宿主认证管理办法处理。

排错截图必须避开二维码和完整链接。向维护者说明状态、版本和错误文字即可。

## 安装被发布冷静期拦住

可能看到：

```text
ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION
```

pnpm 可以要求新发布的依赖等待一段时间后才能安装。检查可能覆盖整份锁文件，所以本次安装的是本地移动插件，也可能因其他已有插件的版本太新而失败。

查看错误列出的具体包名、版本、发布时间和截止时间。默认等到策略允许后再重新安装，不要连续重试。不要删除或重建现有锁文件，也不建议全局把冷静期设为零来装一个布局插件。

维护者可以审核错误中精确包名与版本是否符合官方例外条件；本教程不提供泛用例外配置。默认仍是等待策略允许后再试。

失败后回到管理器确认实际状态。输入安装路径、检查通过、安装完成和启用成功分别是不同阶段；没有“安装成功”结果时，不要只靠刷新判断已经生效。

## 包哈希不一致或管理器不接受包

- 从[同一次 Release](https://github.com/MuQY1818/ds-bot-mobile-web/releases)重新下载 `.tgz` 和 `SHA256SUMS`，核对版本与文件名。
- 确认下载的是插件附件，不是 GitHub 自动生成的源码压缩包。
- 不要解压后手动改文件再继续使用原校验值，也不要把旧包改成新版本的文件名。
- 管理器里使用的是电脑上的本地文件路径；手机的下载路径、Release 网页地址都不能替代它。
- 若提示运行时版本不兼容，查看对应发布说明，在隔离模拟环境验证；不要为正在运行的桌面 DSH 再开第二套 profile，也不要替换已有 DS Bot 或忽略不兼容结果。

具体校验命令见[安装教程](installation.md#2-下载发布包并核对-sha-256)。

## 已登录，但仍显示旧布局

1. 在安装插件的那套 DSH 中确认 `dsh-mobile-layout-local` 已安装、版本正确且 bundle 已启用。
2. 在手机刷新当前页面；必要时关闭这个标签页，从已认证入口重新打开。
3. 检查是不是宽屏或浏览器启用了桌面网站模式。桌面宽屏保持原桌面布局，不能据此判断插件未加载。
4. 检查当前浏览器是否曾选择“原版”。用页面上的“手机布局”按钮，或 DSH 插件设置页中的“启用手机布局”开关重新开启。
5. 确认手机访问的是安装了插件的宿主，而非另一个旧入口或测试实例。

布局选择保存在当前浏览器，不会自动同步到其他设备。浏览器限制本地存储时，选择可能无法跨刷新保留。

## 手机界面打开了，但发送或卡片操作失败

实际发送、附件、问答和审批仍由原 DSH／DS Bot 处理。先看原版会话的错误提示和连接状态，确认当前会话、模型和权限可用。

遇到发送结果不明确，先等待连接恢复并查看历史，不要连续重复提交。布局插件不增加后台恢复后的自动重发。手机返回列表再进入会话，可以检查当前内容；需要刷新时先保留未确认的草稿。

附件选择、语音和部分卡片可能受浏览器能力或权限影响。单个文字消息成功不能证明所有卡片都兼容；同样，构建和控制器测试通过也不能代替真机上的完整流程。报告问题时说明具体是哪一种卡片及哪一步失败，不要公开真实消息、附件或密钥内容。

## Safari 键盘遮挡、滚动异常或后台回来不同步

可以先收起键盘，确认输入区是否恢复；再尝试切换屏幕方向、同步当前会话或刷新。刷新前保留重要草稿，连接恢复后先检查消息是否已提交。

若问题持续，切回“原版”判断是否仍存在。记录手机系统与浏览器版本、横竖屏、是否从后台恢复、使用的网络类型，以及最短复现步骤。Safari 软键盘、安全区、锁屏和长后台流程尚未全部覆盖，不能用 Chromium 的窄窗口截图保证这些行为。

## 精灵形状与电脑上不同

本插件从固定上游源码打包必要精灵组件，使用独立 registry。第三方插件运行时注册的自定义 shape 不一定自动共享到这里，因此可能与原界面显示不同。

先检查是否使用内置精灵或普通头像图片，以及颜色、工作状态是否正确。只有第三方 shape 不一致时，保留该插件名与版本并报告兼容问题，不要以此推断 Bot 资料或会话丢失。实现边界见[架构与边界](architecture.md)。

## 升级后冲突或想恢复旧版

当前页面先点“原版”。如果需要停用整个插件，在 DSH 插件管理器停用 `dsh-mobile-layout-local` bundle，然后刷新。

升级前应保留旧 `.tgz`、对应校验值和版本记录。需要降回旧版时，使用管理器支持的卸载或重新安装流程，只处理这个布局 bundle。不要删除 DS Bot、团队或聊天数据，也不要用旧 profile 备份覆盖正在变化的团队数据。

如果卸载或重新安装又被锁文件检查拦住，先保持 bundle 停用，按具体包管理错误处理。停用恢复和包管理事务不能混为一谈。

## 报告问题时提供什么

可在[项目 Issues](https://github.com/MuQY1818/ds-bot-mobile-web/issues)提供：插件版本、DSH／DS Bot 版本、系统与浏览器版本、错误文字、最短操作步骤，以及切回原版后是否仍会发生。网络问题说明使用局域网、Tailscale 或其他代理即可，无需公布真实域名。

请去掉账号资料、用户目录、团队内容、真实域名、登录链接查询参数、二维码、cookie、token 和密钥。只截取错误区域，并先检查终端或网络记录里是否带有认证信息。未经脱敏的启动日志和完整页面截图不要上传。
