# Mobile Web 网络开销与验证

记录日期：2026-10-18。本记录对应 `0.4.1`。性能和消息测试使用独立 DSH `0.2.1-rc.2`、固定 DS Bot 源码和 mock 模型，不读取生产 profile 或向真实会话发消息；实际宿主安装核验单独记录于文末。

## 瓶颈与改动

DS Bot 已每 1.5 秒查询一次团队状态。Mobile Web 旧版在同页额外每 1.5 秒查询一次，即使桌面宽屏下手机界面隐藏，也会继续查询。每次打开会话还会独立查询当前 Bot / 群与 Session 的映射。

本次只调整两处：

1. Mobile Web 的团队元数据改为请求结束后间隔 5 秒再查询；仅在手机布局启用、符合手机视口且页面可见时运行。返回前台、恢复在线、切入手机视口和主动同步仍立即恢复状态。DS Bot 自身轮询与 DSH 的实时 Session 流继续工作。
2. 同一 Mobile client 的并发状态查询共享在途请求。点开会话仍验证当前身份，不使用已完成的旧响应跳过校验。取消某个导航只移除自己的等待者；最后一个等待者取消时才中止网络请求。过期响应不能写回新状态，401/403 清除增量身份快照。连续点开其他会话、返回列表和卸载均取消旧导航。

没有修改 DSH 核心、全局 fetch、认证或消息发送逻辑。Mobile Web 不把团队 metadata 写入聊天 transcript，也没有新增乐观消息或自动重发；用户消息与回执去重由原生 Session / composer 管理。

## 隔离页面测量

采用同一 Chromium 页面、相同隔离宿主和团队数据。通过 Resource Timing 统计完成的 `/api/bot` HTTP 请求，每个窗口 30 秒，无用户操作；数量包括 DS Bot 自身轮询，不能当作仅 Mobile Web 的请求数。

| 状态 | 请求数 / 30 秒 | 范围 |
| --- | ---: | --- |
| 修改前 | 40 | DS Bot 与 Mobile Web 各自轮询 |
| 修改后，390px 手机视口 | 25 | 本次窗口较基线减少 37.5%；边界处计时可带来一次差异 |
| 修改后，1440px 桌面视口 | 20 | 手机元数据轮询停止，保留 DS Bot 轮询 |

这些是本机隔离测量，不是手机公网速度或延迟承诺。宿主负载、代理 RTT、浏览器节流和窗口边界都会影响结果。

## 缓存、消息可见性与草稿

- 当前页面内最近 3 个会话保留 5 分钟的 canonical Session 引用；缓存不跨刷新或页面回收持久化。没有新增 transcript 副本、凭据存储或跨身份共享。
- 已有引用缓存测试继续覆盖 Session 轮换、删除、401/403、打开失败、TTL、LRU 和迟到释放。新的请求合并不跳过再次打开时的身份检查。
- 在原生 renderer / composer 中发送合成单聊文字，按 Enter 后检测到用户气泡约 162 ms；群聊约 63 ms。这两个数包含自动化调用开销，仅证明该隔离场景无需退出重进就能显示，不能代表公网真机。
- 单聊等待 mock 回复后，切到另一个会话再返回，用户气泡仍为 1 条；没有追加重复项。使用浏览器内 click 时间与 DOM observer 测量，缓存返回后消息显示为 56 ms。
- 浏览器离线模拟期间输入但不发送的草稿，切换其他 Bot 时没有泄漏，返回原会话仍保留，恢复后没有自动提交。
- 本轮未复现“发送后必须退出重进才能看到自己消息”的 Web 故障；App / Bridge 使用独立链路，需要单独诊断。

上述验证不覆盖所有 Safari 真机、锁屏、长后台、网络切换或未确认发送结果的组合。

## 首次资源加载

隔离页面已使用 gzip 加载插件批量资源，响应带 `public, max-age=31536000, immutable`。最大的插件批量响应约 5.38 MB 编码 / 10.63 MB 解码，说明首次加载仍包含较大的宿主和插件集合；不能将此总量全部归给 Mobile Web。

本次检查的一个 DSH `/assets/*.js` GET 响应有 gzip，但没有 Cache-Control、ETag 或 Last-Modified。该静态资源路由属于 DSH；本分支没有拦截它或绕过认证缓存。后续可在受控入口中单独评估带内容哈希的静态资源缓存，需与认证/API/登录响应严格区分。

同日经正式插件管理器安装并启用 `0.4.1`，安装结果为 `applied`；8 个包内文件与已验证归档逐字节一致。共享手机访问入口返回 HTTP 200，现有私人转发处于 ready；App 配套插件和 Bridge 版本保持兼容。该检查只证明安装与连接入口状态，不是 Safari 真机上的性能对照测试。

## 0.4.3：启动资源与近期会话

本地实际宿主响应测得，首屏所需核心和插件资源合计约 6.74 MB 传输、18.21 MB 解码。几个大插件资源已有长期缓存，两次页面响应中的资源地址相同；基础四个脚本/样式合计约 557 KB，缺少明确缓存策略。该测量来自电脑本地响应，不是手机链路耗时。

本版在空闲时缓存这部分带版本标记的基础静态文件，并在后续打开时复用。首屏提示在大型脚本前加载；近期会话在取得最新团队信息后串行预热，最多两个目标，复用原有三个会话引用上限。首次下载、脚本解析、电脑唤醒及 Tailscale 连接仍会耗时。

缓存不包含 HTML、登录或 API 响应，也不另存一份聊天历史。浏览器清理站点数据、存储空间不足或不支持 Worker 时，正常退回网络读取。

## 0.4.4：大型代码缓存与并行恢复

持久缓存范围扩展到宿主 `/plugins/` 的严格固定版本代码协议，且要求响应明确声明公开、不可变。聊天 API、登录、页面与调试映射不缓存。缓存设置有容量条目限制，停用后清理；浏览器存储不可用时回退网络。恢复时独立读取会话目录与团队信息，不再相互等待。

隔离移动浏览器中，清空普通 HTTP 缓存后重新打开，核心 JS/CSS 和插件 JS 均由 Worker 提供，宿主未再收到这些资源的请求。加载反馈等待移动界面及首轮状态就绪再淡出。此结果验证缓存与启动时序，不代表手机总耗时已达到相同水平。首次下载、JavaScript 解析、手机链路与电脑唤醒仍会耗时。

## 0.4.5：真实桌面入口样本与反馈边界

2026-10-19 在实际 iPhone 桌面入口取得一组页面计时：导航开始到移动界面就绪约 2.26 秒，HTML 首字节约 0.55 秒；页面出现约 1.32 秒的事件循环停顿。静态缓存中已有四个核心与四个插件资源，代码请求均有 Worker 参与，主要代码在各自开始后约 34–42 ms 完成。单凭 Resource Timing 的零传输字节不能精确区分普通缓存与 CacheStorage。

用户仍观察到点击桌面图标后的长白屏。上述计时从页面导航开始，未覆盖系统在此之前的唤起过程，也不是完整桌面启动耗时的测量；不能用该单次样本宣布约十秒的体验已解决。

本版给常见 iPhone 增加系统使用的静态启动图，并将页面内加载动画放到独立于 React 根节点的实际元素中。它们改善等待期间的反馈，不能缩短系统唤起或消除大型宿主脚本的执行时间。没有缓存带身份的 HTML、聊天 API 或登录响应。临时诊断仅记录数字、固定资源分类与缓存状态，不记录资源 URL、查询参数、聊天内容或凭据，且不随正式插件启用。
