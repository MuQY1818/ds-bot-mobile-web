# 常见问题

## 手机要安装什么？

使用 Web 只需要现代浏览器。`ds-bot-mobile-web` 安装在电脑的 DSH 中，手机不安装 `.tgz`，也不需要原生 App 或 Bridge。使用 Tailscale 私网时，手机仍需安装并连接 Tailscale。

## iPhone 和 Android 都能用吗？

Web 是主要入口，采用响应式布局，面向 iPhone Safari、Android Chrome 等浏览器。不同系统的软键盘、长后台和网络切换仍需持续验证；遇到问题请说明系统和浏览器版本。

## 添加桌面后就是离线 App 吗？

不是。它是方便打开网站的入口，仍需联网并访问运行中的电脑。系统可能回收网页，下一次打开便会重新加载。当前没有完整离线聊天或每次秒开的承诺。

## 为什么点回一个对话还会加载历史？

当前页面会短期保留最近 3 个会话，保留窗口为 5 分钟。0.4.16 起，后台切换不再额外触发 30 秒清理。刷新、页面被回收、会话轮换或超出窗口后，需要重新读取。这个缓存不会把所有聊天长期保存为第二份转录。

## 冷启动慢正在解决吗？

当前 0.4.6 保留自 0.4.3 / 0.4.4 起加入的基础资源与固定版本插件代码缓存，并在空闲时预热近期会话。首次加载完成后，页面会在空闲时准备缓存；后续打开可复用这些静态资源。首次下载、网络连接和历史同步仍需时间，清理站点数据后缓存也会消失。详细边界见[状态页](status.md)。

iPhone 桌面入口在网页脚本运行前使用系统启动图，进入页面后显示旋转加载指示。前一阶段的图片是静态的；系统唤起、电脑连接与脚本执行仍可能需要等待。

## 电脑关机、休眠后还能聊吗？

不能。手机连接的是你自己的电脑，DSH 与网络入口需要运行。唤醒电脑、恢复私网后重新打开即可。

## 每次都需要扫码吗？

通常不需要。登录保存在当前浏览器和入口中；会话失效、换浏览器、无痕模式、清理站点数据或更换入口后，可能需要重新扫码。

短暂断网和切回前台不应让登录过期。0.4.16 会自动恢复连接，网络错误不会要求换 token。电脑生成的扫码链接使用启动 token；浏览器首次扫码后使用持久 cookie，日常请打开干净的普通 HTTPS 地址。

DSH 的 `connection.cookieMaxAgeDays` 默认是 30 天。个人设备需要更长有效期时，可以在所用 profile 的用户 patch 中合并以下字段，保留该行的其他设置：

```yaml
- id: connection
  config:
    cookieMaxAgeDays: 365
```

这是新签发登录的有效期，不会延长已经签发的 cookie；原登录在原到期时间内仍有效。签名密钥保存在宿主凭据中，正常重启不会使浏览器登录失效。不要删除该记录或清理站点数据。iOS 清理页面内存只会丢失内存缓存，并不等于登录凭据失效。

## Web 登录码和 App 配对码有什么区别？

Web 二维码登录浏览器；App 二维码发起原生设备配对，还需要电脑批准。只用 Web 时不需要 App 配套插件或 Bridge。

## 会新建或迁移我的 Bot 团队吗？

不会。插件复用当前 DSH 与 DS Bot。安装、升级或停用移动布局无需重建团队。

## 遇到问题先做什么？

先看[故障排查](troubleshooting.md)，记录设备、浏览器、错误文字和复现步骤。反馈时遮住二维码、完整登录链接与私人会话。
