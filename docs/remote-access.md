# 远程访问与登录配置

移动布局解决“手机怎么用”，网络入口解决“手机怎么连到电脑”。两者需要分别配置。`127.0.0.1` 和 `localhost` 都表示当前设备自身，手机不能用电脑页面里的本机地址访问电脑。

本插件复用 DSH 的官方浏览器认证，不附带公网隧道，不修改路由器、DNS 或防火墙，也不替你添加受信任域名。优先使用已经能访问同一支 Bot 团队的私网 HTTPS 入口。

## 已有可用入口

1. 确认手机能访问你的 HTTPS 地址。使用 Tailscale 等私网时，电脑和手机需要登录相同的网络，并满足该网络的访问规则。
2. 在电脑本机的 DS Bot 页面打开左下角账户菜单，点击“手机访问”。
3. 如果宿主公布的地址已经可用于手机，面板直接显示二维码。否则填写你的干净 HTTPS 地址，例如 `https://dsh.example.com/`，再点“保存并检查”。不要填写带 `token` 的旧登录链接。
4. 插件会检查这个地址是否被宿主信任。通过后，宿主为该地址生成官方登录链接，二维码在电脑本地生成。
5. 手机扫码，或通过自己的设备同步方式传递“复制登录链接”得到的地址。登录后可以收藏普通 HTTPS 地址。

保存地址只更新此插件的 `phoneUrl` 字段，不会建立网络连接或修改宿主的信任列表。若提示未受信任，应先完成宿主配置。不要把一个本机签名链接的主机名手工改成私网域名，签名中的访问范围可能不匹配。

## 可选：使用已有 Tailscale 私网

Tailscale 是一种选择，并非插件依赖。需要电脑和手机均安装、登录且连接 Tailscale。由网络管理员确认访问权限；不要把私网入口误设成公网 Funnel。

以下例子只用于你**已经在 `web` profile 中运行同一支 DS Bot 团队**、并且可以使用 `dsh` CLI 的环境。桌面版正在运行时，不要照抄命令另起一个 profile，也不要启动两套进程争用同一份团队数据。

先在电脑上检查自己的 Tailscale 状态，并按 Tailscale 当前版本的帮助配置 Serve：

```sh
tailscale status
tailscale serve --help
```

对于一个已经通过官方方式监听电脑本机 `8080` 端口的 DSH Web，Serve 的示意命令是：

```sh
tailscale serve --bg http://127.0.0.1:8080
```

这会配置网络转发，不会替 DSH 建立浏览器会话。按命令输出取得你自己的 HTTPS 设备域名，再确认 DSH 信任这个准确的域名。动态端口环境还需要让转发目标跟随实际端口；本插件不会自动修改现有 Serve 配置。

## 独立 Web 部署的官方参数

DSH `0.2.1-rc.2` 的 Web 帮助提供了 `--public-url` 和 `--trusted-host`。在计划好的启动或维护窗口里，已有 `web` profile 的示例为：

```sh
dsh --profile web --port 8080 \
  --public-url https://dsh.example.com/ \
  --trusted-host dsh.example.com
```

把示例域名换成你自己已经配置好的 HTTPS 入口。例子使用文档保留域名，不能直接用于访问。若有显式端口，信任项也应按当前 DSH 帮助填写准确的 authority。

这两个参数的作用不同：

| 参数 | 作用 |
| --- | --- |
| `--public-url` | 告诉宿主应公布哪个 Web 地址，供启动登录链接和插件读取；本身不授予信任 |
| `--trusted-host` | 允许对应的 Host／Origin 通过浏览器访问边界；不代替登录认证 |
| `--port` | 选择 DSH 监听端口；代理目标必须与实际监听一致 |

反向代理应按 DSH 的部署要求转发请求，并正确处理原地址的路径。如果使用挂载前缀，`--public-url` 和“手机访问地址”都应包含该前缀。不要只修改浏览器地址栏，也不要用通配域名代替明确的信任配置。

桌面版用户应使用该版本支持的配置入口设置等效的 `publicUrl` 和精确 `trustedHosts`，不修改应用安装包。本插件不负责接管桌面宿主的启动或替它重启。先在电脑运行 `dsh --profile web --help` 核对当前版本参数；如果现有桌面集成已经提供手机入口，直接复用即可。

## 为什么二维码只在电脑本机签发

“手机访问”接口要求：本机连接、当前监听端口的本机 Host、同源请求、已认证的浏览器所有者会话，以及一个已被宿主信任的 HTTPS 目标。远程手机即使已经登录，也不能通过这个面板为其他设备生成新的登录链接。

二维码不是公开分享页面。链接包含 DSH 的访问凭据，请只传给自己的设备。关闭弹窗会清理本插件持有的链接和二维码，但不表示撤销已复制的链接或已有登录会话。“刷新入口”重新读取当前官方登录入口，不会承诺旋转宿主的进程凭据。宿主重启后重新打开面板获取链接。

如果链接已经意外公开，按 DSH 的认证管理办法撤销或轮换相关访问，不要只删除截图。

## 如何判断问题在哪一层

| 看到的情况 | 优先检查 |
| --- | --- |
| 手机连接超时、域名无法打开 | 电脑是否运行、私网是否连接、HTTPS 代理是否指向当前端口 |
| `dsh web authentication required` | 网络已经到达宿主，但当前浏览器缺少有效会话；回电脑重新扫码登录 |
| 面板提示地址未受信任 | 目标域名是否已进入宿主的精确 Host／Origin 信任配置 |
| 已登录但仍显示原版界面 | 移动插件是否启用、页面是否刷新、此浏览器是否曾选择“原版” |
| 电脑重启或端口变化后无法连接 | 重新核对实际监听端口、代理目标和新的官方登录入口 |

更多具体处理见[故障排查](troubleshooting.md)。
